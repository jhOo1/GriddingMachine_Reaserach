# GriddingMachine论文补充材料（仓库复审同步）

## S1 从目录更新到模型参数组织的Julia示例

以下示例对应正文2.4节，依次完成数据目录配置与更新、ELEV产品完整性下载、US-NR1附近格点读取和2020年第二套陆面参数集合（`gm2`）的参数组织。`gm2`由14类土壤、冠层、叶片、地形、陆地掩膜和植物功能型标准产品组成。

| 数据操作 | 公共接口 | 主要输出 |
|---|---|---|
| 配置数据环境 | `configure!` | 数据根目录与目录来源 |
| 更新产品目录 | `update_database!` | 通过schema校验的版本化目录 |
| 获取标准产品 | `download_dataset!` | 事务式获取；对带`SIZE`/SHA-256条目可执行严格完整性核验 |
| 读取规则网格 | `read_dataset` | 整场、周期或站点数据 |
| 融合陆面参数 | `grid_dict` | 格点级模型参数字典 |
| 组织气象驱动 | `grid_weather` | 格点级气象时间序列 |

真实气象案例在US-NR1读取2020年8类ERA5标准产品。八文件共12 575 376 138字节，各字段包含8784个逐小时值；`grid_weather`与`NetcdfIO.read_nc`底层读取的最大绝对差均为0，FDOY与经度时区公式逐点一致。真实陆面参数和气象驱动共同通过Emerald初始化及60 s首步。单位审计确认PPT按米水层解释；修订制品以V1_R1物理文件发布到机构FTP，原V1保留，正式目录的V1逻辑标签指向R1。FTP回下载和全新Collector获取均通过SIZE/SHA-256与结构核验。逐文件SHA-256、值域和环境见`experiment_data/03_09/real_era5_result.toml`及`论文/experiments/03_09_ERA5真实气象链路实验结果.md`。投稿代码与研究材料通过带注释Git标签冻结，标签、精确提交号及PPT R1制品摘要统一记录于`论文/投稿版本锁定.toml`。

```julia
using GriddingMachine
using GriddingMachine.Collector
using GriddingMachine.Indexer

Collector.configure!(home = joinpath(homedir(), "GriddingMachine"))
Collector.update_database!()

file = Collector.download_dataset!(
    "ELEV_4X_1Y_V1"; require_integrity = true
)
elevation = Indexer.read_dataset(file, 40.0329, -105.5464)
parameters = Indexer.grid_dict("gm2", 2020, 40.0329, -105.5464)
```

目录和标准产品也可来自完成归档与完整性核验的研究材料。此时通过`catalog_file`和数据根目录指定相应副本，后续读取及模型参数组织保持相同接口。

## S2 Collector目录维护接口

Collector在单标签获取之外提供目录更新、全库同步、历史数据整理、目录树和数据集信息查询。`sync_database!`在更新目录后遍历有效标签并复用事务式下载逻辑；历史数据整理依据当前有效目录识别版本状态；路径、URL、完整性元数据和本地文件状态通过统一查询接口呈现。目录更新、同步和数据获取共享schema校验和临时文件落盘逻辑；当目录条目提供`SIZE`与`SHA256`时，可启用严格完整性核验。历史兼容条目若缺少这些字段，不计入本文严格完整性结论。

## S3 配置与贡献材料

完整YAML字段字典、数据贡献目录结构、产品登记步骤及状态恢复命令随论文对应的软件release归档。正文仅保留解释生产契约所需的字段类别与转换示例；完整YAML、字段字典和版本化指南在补充材料及release中提供，覆盖二维和三维产品、`data/std`组合及批量产品配置。

本地交互式配置生成器提供表单化输入、YAML预览与保存功能。界面提交的结构化参数由`YamlBuilder`转换为配置对象，并使用与`process_dataset!`相同的schema完成字段解析。交互界面与程序化构建方式由此生成结构一致、可直接进入标准产品生产流水线的YAML配置。

## S7 术语、目录覆盖与PPT修订案例

### S7.1 操作性定义

- **可信分发（trustworthy distribution）**：版本化目录、镜像回退和独立临时文件共同组织获取；对于登记了`SIZE`和SHA-256的条目，可在严格模式下核验内容身份后再进入正式目录。该术语关注目录登记对象与下载内容的一致性，数据源真实性、科学质量和长期服务可用性分别由上游质控和运行环境记录。
- **模型就绪（model-ready）**：标准产品经格点索引、字段组织、时间轴构建和量纲衔接后形成满足本文所测试Emerald初始化接口的数据结构，并可完成60 s首步。本文的评价范围集中于数据组织、初始化和首步接口运行。
- **跨操作系统运行一致性**：固定依赖和既定测试路径在Windows、macOS和Linux中的结构、数值、摘要和状态结果满足相同判据，用于描述核心实现的跨平台运行一致性。

### S7.2 目录覆盖边界

目录覆盖率反映数据发布和镜像迁移进度。审计时1179个条目均已登记机构FTP地址，其中部分产品进一步完成Zenodo等公共镜像登记；`SIZE`/SHA-256可由权威文件批量计算并随发布过程回填。目录schema统一支持多个URL和完整性字段，Collector按照已登记镜像执行获取与核验。正文中的严格完整性和真实多镜像实验采用已经完成相应配置的代表性产品。

### S7.3 逻辑标签与物理制品修订

ERA5降水产品提供真实修订案例。逻辑标签保持`PPT_ERA5_1X_1H_2020_V1`，修订后的物理文件为`PPT_ERA5_1X_1H_2020_V1_R1.nc`。原V1物理文件保留，目录将V1逻辑标签的URL指向R1并登记：

- 字节数：`1102213097`；
- SHA-256：`1ae6b80512fac97e6b3e609c02ea126858256cf9153ead1335b5bf8d59fe7725`；
- 全新Collector按V1逻辑标签首次获取R1并通过严格完整性核验；
- 第二次调用复用正式缓存，没有再次访问网络；
- 获取过程未遗留`.part`临时文件。

该案例说明稳定逻辑身份可以与可修订物理制品解耦；原始V1、修订R1及其独立摘要共同保留版本边界。原始记录见`experiment_data/03_09/ftp_r1_release_result.toml`和`experiment_data/03_09/collector_ftp_r1_result.toml`。
