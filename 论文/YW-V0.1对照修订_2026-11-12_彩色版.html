修改前

修改后

标准网格读取接口可按本地NetCDF路径或数据标签访问数据，支持读取文件覆盖的全部空间网格、指定周期的空间切片，以及站点的全部周期或指定周期数据，共4种方式。按标签调用时，目录模块自动获取对应文件。接口默认读取标准变量`data`，也可读取文件中可选的原始数据变量`raw_data`或形状相同的不确定性变量`std`。各读取方式采用一致的维度、单位和缺失值约定，便于后续组合模式输入。 站点读取根据全球规则经纬网的分辨率，将目标经纬度换算为数组索引。输入文件的维度顺序为`(lon,lat[,ind])`，经度自西向东、纬度自南向北排列。接口直接提取对应格点的数据；区域投影、非规则网格转换和空间插值可在数据生产与标准化层完成。周期索引表示月份、日期还是小时，由相应数据的元数据说明。 #### 2.10.2 模式参数与气象驱动组织 陆面参数由同一目标位置和年度的多源数据组合而成。接口从预定义集合中提取土壤、冠层、叶片、地形、陆地掩膜和植物功能型数据，按各自网格分辨率定位目标格点，再依据陆面状态融合参数。叶面积指数、叶绿素、冠层聚集度和最大羧化速率等季节序列统一到逐日时间轴。完成缺失值填补后，月尺度数据按各月实际天数展开，8日尺度数据按覆盖日期展开，并依据年份保留365或366日。本文第二套陆面参数集合`gm2`包含14类标准化数据，其中冠层聚集度采用月尺度数据集。 叶片光学参数与Medlyn气孔导度模型参数分别按采用C3和C4光合途径的植物组织[6,7]。C3参数按格点内对应植物功能型的比例归一化加权，C4参数从相应类型的参数表提取，以保留两类植物的参数差异。叶片羧化能力与电子传递能力的关联为光合参数组织提供依据[8]。本研究采用GriddingMachine模式输入接口的固定比例参数化，根据25 ℃下最大羧化速率`VCMAX25`计算最大电子传递速率`JMAX25`和细胞色素b6f复合体含量`B6F`，换算关系、参数单位与实现出处见补充材料S1。输出包括位置、分辨率、年份、二氧化碳（CO₂）、土壤水力性质、冠层结构、植物功能型组成、叶片生物物理和光合参数，同时检查字段是否完整以及缺失值标记`NaN`的分布。经过上述处理，多源数据形成结构一致的格点级模式输入。 气象驱动组织将同一格点、同一年度的变量组成逐小时序列。气象驱动集合`wd1`包含8类第五代全球再分析数据（ERA5）[9]：地表气压、降水、漫射与直射短波辐射、长波辐射、气温、水汽压亏缺和风速。接口可按经纬度提取对应格点，也可从已加载的全域气象数组中索引序列。时间轴采用浮点年积日（fractional day of year，`FDOY`）：按模式驱动接口的约定，将协调世界时（Coordinated Universal Time，UTC）年度序列中的各小时标记置于小时中点，再以经度除以15得到的小时偏移转换为地方平太阳时，用于Emerald的太阳天顶角计算。经纬度调用采用输入位置的经度，数组索引调用采用格点中心经度；完整公式见补充材料S1。输出同时检查字段完整性和缺失值状态，使气象序列与模式时间计算采用明确的对应关系。 网格读取提供各变量的数值，参数和气象驱动接口则将这些数值按字段、时间与量纲关系组织为模式输入。本文所称“模式就绪”，是指标准化数据经过格点提取、参数融合、时间轴构建和量纲换算后，能够满足Emerald初始化接口的数据结构要求。2022版主要通过标签提供基础数据访问[5]，新版进一步组合多源数据，形成可由模式直接调用的输入，使科研程序能够复用数据及其组织方法。完整调用示例见补充材料。 ### Process source data using the prepared YAML configuration. process_dataset!("dataset.yml") ``` 其中，`dataset.yml`为已设置输入文件及处理规则的配置文件。 ### 2.2 数据文件共享 标准化文件可通过Zenodo、ScienceDB等科研数据平台共享，也可由机构服务器提供镜像。公共科研存储减少了对单一机构服务器的依赖；同一文件在不同位置保存，则使研究人员可以从多个地址获取数据。 标准化数据以单个NetCDF文件作为共享单元，文件名与数据标签对应。2022版GriddingMachine（v0.2）将NetCDF文件经外层`tar.gz`压缩后分发，使用前需要解压；新版GriddingMachine（v0.5）直接分发NetCDF文件，使下载后的文件可以直接用于读取，减少了数据获取与使用之间的处理步骤。 文件通过超文本传输协议（HTTP/HTTPS）或文件传输协议（File Transfer Protocol，FTP）地址提供下载，同一数据标签可登记多个镜像。下载地址和文件完整性信息由数据库文件统一记录。分发位置调整时，数据提供方更新相应记录，科研程序继续通过标签获取数据。 ### 2.3 数据库文件 数据库文件记录数据标签、文件位置及相关信息。我们将软件包内的`Artifacts.toml`改为独立维护的`Artifacts.yaml`，使新增数据或调整下载地址不必伴随软件发布。数据库文件采用YAML文本格式，并通过Zenodo保存不同版本。研究人员可保留试验所用的数据库文件，以记录当时选用的数据和下载地址。 每个数据标签对应一个条目，其中本地相对路径（`PATH`）确定文件的保存位置，下载地址（`URL`）列出可用镜像，文件字节数（`SIZE`）和文件摘要（`SHA256`）用于核对下载内容。登记工具根据标准NetCDF文件计算字节数和SHA-256摘要，再将其与下载地址一并写入数据库文件。Collector据此查找和获取文件，Indexer读取相应数据；数据库内容和软件功能因而可以分别更新。 以中分辨率成像光谱仪（Moderate Resolution Imaging Spectroradiometer，MODIS）的2020年叶面积指数数据为例，数据库文件中的记录如下。这里展示其中一个下载地址，多个镜像可依次列在`URL`下： ```yaml # One download address from the existing LAI catalog entry. LAI_MODIS_2X_8D_2020_V1: PATH: "public/v0" SIZE: 13936426 SHA256: >- fda32f694a38d9d3c5244cd5bd739825c7441c918d91e56442a553ab4fa5d0df URL: - >- https://zenodo.org/records/17732092/files/LAI_MODIS_2X_8D_2020_V1.nc ``` 示例标签中的`LAI`表示叶面积指数（Leaf Area Index），`2X`表示0.5°空间分辨率，`8D`表示8日时间分辨率，`2020`和`V1`分别表示年份和数据版本。同一标签通过数据库文件关联相应文件及下载地址。 研究所用目录版本收录1179个数据条目，包括高程与陆地掩膜、土壤水力性质、植被结构与叶片属性，以及气象驱动等数据。地形和土壤属性用于描述格点的基础陆面条件，植被数据包含季节变化信息，逐时气象数据提供模式运行的外部驱动。数据标签记录类别、空间与时间分辨率、年份和版本，并与文件名对应；数据修订时，可在文件名中附加修订号。各条目登记机构FTP地址，部分同时配置Zenodo镜像。目录版本与统计记录见补充材料S7。 ### 2.4 Collector：数据自动化下载 Collector根据数据库文件下载数据，并管理本地文件。程序优先读取本地`Artifacts.yaml`；该文件不存在时，从配置的远端地址获取。研究人员可指定数据库文件的来源，也可主动更新，以获取新增或修订的数据。更新过程中，程序先检查新文件的结构和字段，再替换本地数据库文件，并保留上一有效版本。 获取数据时，Collector先根据标签查找本地文件。已有文件符合目录记录时，直接返回本地路径；否则尝试目录中的下载地址。新文件先下载到临时位置，按登记的完整性信息核验后，再移入正式位置。若某个镜像无法访问或文件未通过核验，程序继续尝试其余镜像；全部下载失败时，保留原有文件。候选镜像可依据访问延迟排序。除单个数据集外，Collector还提供选定标签的批量同步和全库同步，便于维护本地数据库。目录字段与调用示例见补充材料S2。 例如，更新数据库文件后，可按上述叶面积指数数据的标签获取文件： ```julia using GriddingMachine.Collector # Refresh the catalog and obtain the local NetCDF path. update_database!() file_path = download_dataset!("LAI_MODIS_2X_8D_2020_V1") ``` `file_path`为下载或复用的本地NetCDF文件路径，可直接交给Indexer读取。 除Julia的Collector外，我们还完善了Matlab、Octave、Python和R的数据自动下载入口，并新增C和Fortran支持。各语言入口调用同一Python下载程序，因此需要Python 3运行环境。科研程序可提供文件URL，或根据本地数据库文件中的数据标签获取文件；下载时使用相同的镜像与完整性核验规则，获取后可利用相应语言的NetCDF工具读取。接口调用示例见补充材料S5。 ### 2.5 Indexer：数据及数据集读取 Indexer提供单个数据集和多源数据集合的读取功能。单文件接口用于读取某一变量，集合接口则用于组合模式所需的多种参数或气象数据。由于这些数据来自不同来源，其空间分辨率、时间组织和字段定义往往不同，集合读取需要在提取目标位置数据后，进一步统一季节序列的时间轴并组织相应字段。研究人员指定集合名称、年份和位置，即可获得所需的参数或气象驱动。 #### 2.5.1 标准网格数据读取 标准网格读取接口`read_dataset`可按本地NetCDF路径或数据标签访问数据，并根据位置和周期提取所需内容。按标签调用时，Collector自动获取对应文件。接口默认读取标准变量`data`，也可读取文件中可选的原始数据变量`raw_data`或形状相同的不确定性变量`std`，各读取方式沿用标准文件的维度、单位和缺失值约定。 以同一叶面积指数数据和北美通量观测站US-NR1的位置为例，4种读取方式分别为： ```julia using GriddingMachine.Indexer tag = "LAI_MODIS_2X_8D_2020_V1" # +
+处理规则保存在YAML文本配置文件中，包括输入文件、\allowbreak{}源变量名称、\allowbreak{}维度含义、\allowbreak{}单位、\allowbreak{}有效范围和缺失值处理方式。数据提供方可通过程序或本地交互式界面生成配置。新增或更新同类数据时，调整输入文件、\allowbreak{}变量名称及处理参数，即可使用已有转换程序。对于非规则网格和区域投影数据，先由数据源专用预处理程序完成网格或投影转换，再进入规则经纬网的通用处理流程。
+
+程序读取并检查配置后，首先调整数据的维度顺序和空间方向。例如，源数据按纬度、\allowbreak{}经度排列，纬度由北向南，经度范围为0°\ensuremath{\sim}360°时，程序交换维度、\allowbreak{}翻转纬度方向并沿经度循环平移，使数据与经度自西向东、\allowbreak{}纬度自南向北的标准坐标逐点对应。随后按配置中的系数进行线性数值换算，并将超出有效范围的数值标记为缺失。
+
+缺失值填补（gap filling）由配置中的\nolinkurl{GAPFILL}字段指定。数据提供方可根据变量的物理含义，选择保留缺失值，或以常数、\allowbreak{}均值填补陆地区域的缺失值；还可按数据覆盖要求检查陆地区域及全域的缺失情况，并对类别数据进行整数化处理。例如，高程数据（ELEV）采用常数0填补陆地区域缺失值。完整配置与字段说明见补充材料S3。
+
+处理过程中，程序生成带经纬度坐标轴的空间分布图，由数据提供方确认数据的位置和方向。确认后，程序按数据标签保存标准文件，并将实际执行的维度调整、\allowbreak{}数值换算及缺失值填补等变更写入NetCDF变量属性。文件保存后，另由文件验证程序检查维度和变量、\allowbreak{}数组形状、\allowbreak{}数值范围及缺失值分布；对于要求陆地区域数据完整的变量，利用相应分辨率的陆地掩膜进行核查。配置文件记录处理规则，并与配置规范版本（\nolinkurl{SCHEMA_VERSION}）、\allowbreak{}固定输入及代码环境共同归档，便于重新处理数据。
+
+配置完成后，可在GriddingMachineDatasets环境中调用标准化程序：
+
+% Keep each short example compact and together with its explanation.
+\begingroup\singlespacing
+\begin{Verbatim}[fontsize=\small,frame=single,framesep=5pt]
+using GriddingMachineDatasets
+# Process source data using the prepared YAML configuration.
+process_dataset!("dataset.yml")
+\end{Verbatim}
+\endgroup
+
+其中，\nolinkurl{dataset.yml}为已设置输入文件及处理规则的配置文件。
 
 \subsection{数据文件共享}
+
+标准化文件可通过Zenodo、\allowbreak{}ScienceDB等科研数据平台共享，也可由机构服务器提供镜像。公共科研存储减少了对单一机构服务器的依赖；同一文件在不同位置保存，则使研究人员可以从多个地址获取数据。
+
+标准化数据以单个NetCDF文件作为共享单元，文件名与数据标签对应。2022版GriddingMachine（v0.2）将NetCDF文件经外层\nolinkurl{tar.gz}压缩后分发，使用前需要解压；新版GriddingMachine（v0.5）直接分发NetCDF文件，使下载后的文件可以直接用于读取，减少了数据获取与使用之间的处理步骤。
+
+文件通过超文本传输协议（HTTP/HTTPS）或文件传输协议（File Transfer Protocol，FTP）地址提供下载，同一数据标签可登记多个镜像。下载地址和文件完整性信息由数据库文件统一记录。分发位置调整时，数据提供方更新相应记录，科研程序继续通过标签获取数据。
+
 \subsection{数据库文件}
+
+数据库文件记录数据标签、\allowbreak{}文件位置及相关信息。我们将软件包内的\nolinkurl{Artifacts.toml}改为独立维护的\nolinkurl{Artifacts.yaml}，使新增数据或调整下载地址不必伴随软件发布。数据库文件采用YAML文本格式，并通过Zenodo保存不同版本。研究人员可保留试验所用的数据库文件，以记录当时选用的数据和下载地址。
+
+每个数据标签对应一个条目，其中本地相对路径（\nolinkurl{PATH}）确定文件的保存位置，下载地址（\nolinkurl{URL}）列出可用镜像，文件字节数（\nolinkurl{SIZE}）和文件摘要（\nolinkurl{SHA256}）用于核对下载内容。登记工具根据标准NetCDF文件计算字节数和SHA-256摘要，再将其与下载地址一并写入数据库文件。Collector据此查找和获取文件，Indexer读取相应数据；数据库内容和软件功能因而可以分别更新。
+
+以中分辨率成像光谱仪（Moderate Resolution Imaging Spectroradiometer，MODIS）的2020年叶面积指数数据为例，数据库文件中的记录如下。这里展示其中一个下载地址，多个镜像可依次列在\nolinkurl{URL}下：
+
+% Keep each short example compact and together with its explanation.
+\begingroup\singlespacing
+\begin{Verbatim}[fontsize=\small,frame=single,framesep=5pt]
+# One download address from the existing LAI catalog entry.
+LAI_MODIS_2X_8D_2020_V1:
+  PATH: "public/v0"
+  SIZE: 13936426
+  SHA256: >-
+    fda32f694a38d9d3c5244cd5bd739825c7441c918d91e56442a553ab4fa5d0df
+  URL:
+    - >-
+      https://zenodo.org/records/17732092/files/LAI_MODIS_2X_8D_2020_V1.nc
+\end{Verbatim}
+\endgroup
+
+示例标签中的\nolinkurl{LAI}表示叶面积指数（Leaf Area Index），\nolinkurl{2X}表示0.5°空间分辨率，\nolinkurl{8D}表示8日时间分辨率，\nolinkurl{2020}和\nolinkurl{V1}分别表示年份和数据版本。同一标签通过数据库文件关联相应文件及下载地址。
+
+研究所用目录版本收录1179个数据条目，包括高程与陆地掩膜、\allowbreak{}土壤水力性质、\allowbreak{}植被结构与叶片属性，以及气象驱动等数据。地形和土壤属性用于描述格点的基础陆面条件，植被数据包含季节变化信息，逐时气象数据提供模式运行的外部驱动。数据标签记录类别、\allowbreak{}空间与时间分辨率、\allowbreak{}年份和版本，并与文件名对应；数据修订时，可在文件名中附加修订号。各条目登记机构FTP地址，部分同时配置Zenodo镜像。目录版本与统计记录见补充材料S7。

 \subsection{Collector：数据自动化下载}
+
+Collector根据数据库文件下载数据，并管理本地文件。程序优先读取本地\nolinkurl{Artifacts.yaml}；该文件不存在时，从配置的远端地址获取。研究人员可指定数据库文件的来源，也可主动更新，以获取新增或修订的数据。更新过程中，程序先检查新文件的结构和字段，再替换本地数据库文件，并保留上一有效版本。
+
+获取数据时，Collector先根据标签查找本地文件。已有文件符合目录记录时，直接返回本地路径；否则尝试目录中的下载地址。新文件先下载到临时位置，按登记的完整性信息核验后，再移入正式位置。若某个镜像无法访问或文件未通过核验，程序继续尝试其余镜像；全部下载失败时，保留原有文件。候选镜像可依据访问延迟排序。除单个数据集外，Collector还提供选定标签的批量同步和全库同步，便于维护本地数据库。目录字段与调用示例见补充材料S2。
+
+例如，更新数据库文件后，可按上述叶面积指数数据的标签获取文件：
+
+% Keep each short example compact and together with its explanation.
+\begingroup\singlespacing
+\begin{Verbatim}[fontsize=\small,frame=single,framesep=5pt]
+using GriddingMachine.Collector
+# Refresh the catalog and obtain the local NetCDF path.
+update_database!()
+file_path = download_dataset!("LAI_MODIS_2X_8D_2020_V1")
+\end{Verbatim}
+\endgroup
+
+\nolinkurl{file_path}为下载或复用的本地NetCDF文件路径，可直接交给Indexer读取。
+
+除Julia的Collector外，我们还完善了Matlab、\allowbreak{}Octave、\allowbreak{}Python和R的数据自动下载入口，并新增C和Fortran支持。各语言入口调用同一Python下载程序，因此需要Python 3运行环境。科研程序可提供文件URL，或根据本地数据库文件中的数据标签获取文件；下载时使用相同的镜像与完整性核验规则，获取后可利用相应语言的NetCDF工具读取。接口调用示例见补充材料S5。
+
 \subsection{Indexer：数据及数据集读取}
+
+Indexer提供单个数据集和多源数据集合的读取功能。单文件接口用于读取某一变量，集合接口则用于组合模式所需的多种参数或气象数据。由于这些数据来自不同来源，其空间分辨率、\allowbreak{}时间组织和字段定义往往不同，集合读取需要在提取目标位置数据后，进一步统一季节序列的时间轴并组织相应字段。研究人员指定集合名称、\allowbreak{}年份和位置，即可获得所需的参数或气象驱动。
+
+\subsubsection{标准网格数据读取}
+
+标准网格读取接口\nolinkurl{read_dataset}可按本地NetCDF路径或数据标签访问数据，并根据位置和周期提取所需内容。按标签调用时，Collector自动获取对应文件。接口默认读取标准变量\nolinkurl{data}，也可读取文件中可选的原始数据变量\nolinkurl{raw_data}或形状相同的不确定性变量\nolinkurl{std}，各读取方式沿用标准文件的维度、\allowbreak{}单位和缺失值约定。
+
+以同一叶面积指数数据和北美通量观测站US-NR1的位置为例，4种读取方式分别为：
+
+% Keep each short example compact and together with its explanation.
+\begingroup\singlespacing
+\begin{Verbatim}[fontsize=\small,frame=single,framesep=5pt]
+using GriddingMachine.Indexer
+tag = "LAI_MODIS_2X_8D_2020_V1"
+# Read all grid cells and cycles.
+data = read_dataset(tag)
+# Read the spatial slice for the eighth cycle.
+layer = read_dataset(tag, 8)
+# Read all cycles at the target grid cell.
+series = read_dataset(tag, 40.0329, -105.5464)
+# Read the eighth cycle at the target grid cell.
+value = read_dataset(tag, 40.0329, -105.5464, 8)
+\end{Verbatim}
+\endgroup
+
+上述调用依次返回全部空间与周期数据、\allowbreak{}第8个周期的空间切片、\allowbreak{}目标格点的周期序列及该格点第8个周期的数值。周期索引的时间含义由相应数据的元数据说明，示例中的\nolinkurl{8}对应8日序列的第8个周期。
+
+按经纬度读取时，Indexer根据全球规则经纬网的分辨率，将目标位置换算为数组索引，并提取对应格点的数据。文件采用\nolinkurl{(lon,lat[,ind])}的维度顺序，经度自西向东、\allowbreak{}纬度自南向北排列，与第2.1节的标准化约定一致。投影转换、\allowbreak{}非规则网格转换及所需的空间插值在数据预处理阶段完成。
+
+\subsubsection{多源数据集合读取}
+
+陆面参数集合将土壤、\allowbreak{}冠层、\allowbreak{}叶片、\allowbreak{}地形、\allowbreak{}陆地掩膜和植物功能型数据按模式所需字段组织。研究人员指定集合名称、\allowbreak{}年份和经纬度后，接口按各数据的网格分辨率提取目标格点，并根据陆面状态组合参数。本文采用的第二套陆面参数集合\nolinkurl{gm2}包含14类标准化数据，其中冠层聚集度采用月尺度数据。叶面积指数、\allowbreak{}叶绿素、\allowbreak{}冠层聚集度和最大羧化速率等季节序列经缺失值处理后统一到逐日时间轴，月尺度数据按各月实际天数展开，8日尺度数据按覆盖日期展开，按年份保留365或366日。
+
+参数融合保留采用C3和C4光合途径的植物在叶片光学参数与Medlyn气孔导度模型参数上的差异\cite{ref3,ref4}，并利用叶片羧化与电子传递能力的关联组织光合参数\cite{ref5}。所得参数按统一字段保存，同时检查字段完整性与缺失值分布。具体换算与模式适配见第3.4节和补充材料S1。
+
+气象驱动集合\nolinkurl{wd1}包含8类第五代全球再分析数据（ERA5）\cite{ref6}，包括地表气压、\allowbreak{}降水、\allowbreak{}辐射、\allowbreak{}气温、\allowbreak{}水汽压亏缺和风速。接口按位置和年份提取对应格点的逐小时序列，也可从已加载的全域气象数组中索引数据，并将各变量与相应时间信息共同组织为气象驱动集合。
+
+上述两类集合分别提供模式参数和气象驱动。本文以Emerald为例，将集合输出按其字段和单位要求接入初始化与驱动接口；其他模式可依据自身输入约定进行适配。
+
+在上述站点位置，2020年的陆面参数与气象驱动可分别通过以下调用获得：
+
+% Keep each short example compact and together with its explanation.
+\begingroup\singlespacing
+\begin{Verbatim}[fontsize=\small,frame=single,framesep=5pt]
+using GriddingMachine.Indexer
+# Assemble the land parameter collection at the target grid cell.
+land = grid_dict("gm2", 2020, 40.0329, -105.5464)
+# Organize the hourly meteorological forcing at the same grid cell.
+forcing = grid_weather("wd1", 2020, 40.0329, -105.5464)
+\end{Verbatim}
+\endgroup
+
+\nolinkurl{land}按字段保存陆面参数，\nolinkurl{forcing}组织气象序列及相应时间信息。科研程序可据此提取模式所需字段，无需逐项查找和读取组成集合的数据。

+GMServer用于搭建网格数据查询服务，供科研程序获取指定位置的数据。服务端调用Collector获取或复用文件，再由Indexer提取单数据集、\allowbreak{}陆面参数集合或气象驱动集合中的格点数据。我们将GMServer独立为服务器组件，使本地下载和读取不必加载Genie网络服务框架的依赖，减少安装与首次运行的开销。服务提供方配置数据根目录和数据库文件来源后，注册查询接口并启动服务。

+\begingroup\singlespacing
+\begin{Verbatim}[fontsize=\small,frame=single,framesep=5pt]
+using GriddingMachineServer
+# Register query routes and start the server on port 5055.
+setup_url_input_routes!()
+up_servers!(5055)
+\end{Verbatim}
+\endgroup

+
+服务端按数据标签或集合名称，以及经纬度、\allowbreak{}年份或周期处理查询，获取或复用本地文件后提取所需数据。结果以便于程序解析的JSON（JavaScript Object Notation）文本格式返回，单数据集查询可同时返回文件中可用的不确定性数据。
+
+GMServer还提供查询页面，便于使用者选择数据、\allowbreak{}输入位置和周期并查看结果。数据文件由服务端统一获取和缓存，多个查询可复用已有文件，客户端接收本次查询所需的数据。

+\subsection{Requestor：非下载式数据请求}
+
+Requestor用于在科研程序中向GMServer请求指定格点的数据。研究人员提供服务器地址、\allowbreak{}数据标签、\allowbreak{}经纬度和周期，即可取得所需数值，无需在本地下载完整网格文件，便于开展站点分析或模式计算。
+
+接口支持请求单数据集在指定格点的全部周期或某个周期，接收主变量及可用的不确定性数据，并将返回结果中的缺失值标记还原为\nolinkurl{NaN}。需要重复使用完整文件时，可通过Collector下载后本地读取；仅需指定位置的数据时，可采用Requestor请求。两种方式使用相同的数据标签和格点读取规则。
+
+例如，在同一机器启动上述服务后，可请求同一叶面积指数数据在US-NR1附近格点的周期序列：
+
+% Keep each short example compact and together with its explanation.
+\begingroup\singlespacing
+\begin{Verbatim}[fontsize=\small,frame=single,framesep=5pt]
+using GriddingMachine.Requestor
+server = "http://localhost:5055"
+tag = "LAI_MODIS_2X_8D_2020_V1"
+# Request all cycles and the available uncertainty at the target grid cell.
+series, uncertainty = request_site_data(
+    server, "research", tag, 40.0329, -105.5464)
+\end{Verbatim}
+\endgroup
+
+其中，\nolinkurl{research}为请求记录中的使用者标记；\nolinkurl{series}返回目标格点的周期序列，\nolinkurl{uncertainty}返回文件中可用的不确定性数据，无该变量时为\nolinkurl{nothing}。
+
+通过上述模块，数据提供方可以处理和共享标准化数据，研究人员则可按标签下载文件、\allowbreak{}读取数据集合，或直接请求指定格点的数据。处理规则、\allowbreak{}数据库文件和分发地址分别维护，使新增或修订数据不必同时更新访问软件。表2按各功能环节比较2022版GriddingMachine（v0.2）与新版GriddingMachine（v0.5）的主要差异。
