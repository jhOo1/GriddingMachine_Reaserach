# 表1 2022版与当前论文版本的功能和技术路线比较

比较基于2022年论文及当前冻结代码：`GriddingMachine.jl`的`wyujie@7152680`与`GriddingMachineDatasets`的`wyujie@51cf0fe`。表中“当前版本”只描述代码已经存在的行为；计划增加但尚未实现的功能列入最后一行。

| 环节 | 2022版 | 当前论文版本 | 证据或边界 |
|---|---|---|---|
| 标准数据文件 | 标准NetCDF打包为`tar.gz` artifact | 标准NetCDF以`.nc`直接分发 | 取消外层打包是否改善端到端效率须由3.2节实验判断 |
| 数据目录 | 软件包内置`Artifacts.toml`，随软件版本发布 | 外置`Artifacts.yaml`，可从Zenodo独立更新 | 当前更新依赖Zenodo网页文本结构，无schema检查和回滚 |
| 数据标识 | 标签映射Julia artifact | 标签映射`PATH`和一个或多个`URL` | 当前目录有1 179个标签，其中72个具有多个URL |
| 下载与落盘 | Julia artifact下载、哈希寻址和解包 | `download_dataset!`下载至cache后移动到public | 当前未校验大小或哈希，全部镜像失败后的状态需实验验证 |
| 镜像选择 | 由artifact条目提供下载地址 | 按ping结果排序，异常时依次尝试后续URL | Windows及禁止ICMP场景可能误判，不代表最优吞吐率 |
| 目录更新 | 更新目录通常需要发布软件版本 | `update_database!`可独立刷新YAML目录 | 首次加载可能创建目录并访问网络，尚无离线模式 |
| 数据读取 | `read_LUT`提供按标签和位置读取 | `read_dataset`统一整场、周期和站点读取，`read_LUT`保留为别名 | 仅适用规定的全球规则经纬网；无坐标插值和单位转换 |
| 模型数据组织 | 主要提供标准化数据及通用读取 | `grid_dict`组织陆地参数，`grid_weather`组织8项ERA5驱动 | 当前为固定`gm1/gm2`和`wd1`组合，不是通用模型耦合层 |
| 数据生产 | 数据源专用脚本与人工贡献流程 | YAML描述文件组合、变量和处理规则，流水线生成标准NetCDF | 21份配置尚未完全满足统一schema；维度重排能力有限 |
| 质量检查 | 数据规范、处理日志和发布前检查 | 方向图人工确认、`verify_processed_data!`及URL抽查 | 现有检查未覆盖全部元数据、坐标和值域情形，URL函数仅抽查前10个标签 |
| 本文拟验证的增强项 | 不适用 | 显式维度映射、schema、完整目录检查、大小/哈希校验及安全缓存 | 均须先实现并在冻结release上实验，不能当作当前代码功能 |

**Table 1 Comparison between the 2022 release and the current manuscript version of GriddingMachine.** Implemented behavior is separated from enhancements that require implementation and validation before submission.
