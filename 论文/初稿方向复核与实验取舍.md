# 初稿方向复核与实验取舍

复核依据：`总览.jpg`、`后续论文流程.docx`中的师生讨论，以及当前冻结的`GriddingMachine.jl wyujie@7152680`和`GriddingMachineDatasets wyujie@51cf0fe`。

## 1. 结论

论文继续以“2022版GriddingMachine的框架更新与验证”为主线，方向正确，但不宜把文章写成泛化的FAIR数据平台论文。老师在讨论中反复强调的是数据怎样制作、发布、更新、下载和用于模型，因此论文贡献应收敛为三个闭环：

1. **新数据进入系统**：网页辅助生成YAML，流水线把异构NetCDF转换为标准NetCDF，完成检查、上传、目录登记，并让新贡献者依据文档重复该流程。
2. **标准数据可靠到达本地**：取消外层`tar.gz`，YAML目录独立更新，一个标签登记多个镜像，下载先进入cache，校验大小和SHA-256后再进入public；Collector公共操作具有自动回归测试。
3. **本地数据进入模型**：`read_LUT`演进为`read_dataset`，并由`grid_dict`和`grid_weather`组织Emerald初始化所需的陆地参数与气象驱动。

Server/Requestor涉及端口暴露和服务安全，老师明确要求暂不处理，继续排除在正文核心和实验之外。

## 2. 初稿需要纠正的地方

### 2.1 YAML不是独立创新点

TOML改为YAML主要改善目录可读性和嵌套表达，老师明确称其为“小事情”。正文可以说明它支撑多URL和网页配置，但不能把格式替换本身写成核心贡献，也没有必要进行TOML与YAML的性能比较。

### 2.2 论文release不能等同于当前代码快照

当前代码仍缺少老师要求恢复的SHA校验；网页YAML生成器含硬编码保存路径、遗留`TARBALL`字段，并缺少当前流水线所需的部分字段；发布脚本和现有自动测试也不完整。论文应把现有commit作为审计基线，把修复并测试后的不可变release作为最终实验对象。未进入release的功能不得写为结果。

### 2.3 “完整Emerald模拟”不是当前核心目标

老师要求`grid_dict`提供模型初始化数据、`grid_weather`提供气象驱动。必要证据是字段数值正确、单位与长度正确，并能完成固定格点的Emerald初始化或最小步进。没有必要把完整科学模拟、参数敏感性或模型性能评估扩展为本论文任务。

### 2.4 缺少贡献流程的独立复现验证

老师明确提出把流程交给岳云熙、陶晨飞或新成员，确认其能按步骤完成。该内容可以放在补充材料或网站，但论文至少应报告：参与者是否无需口头干预完成YAML生成、数据处理、检查、上传模拟和目录登记；在哪一步出错；文档据此怎样修订。它比单纯增加更多性能重复次数更贴近论文贡献。

### 2.5 Collector回归测试覆盖不足

讨论中点名`update_database!`、`download_dataset!`、`sync_database!`、`clean_database!`、目录树和信息查询等逻辑。当前初稿重点测试下载故障，却没有把这些公共操作列成完整回归矩阵。必须补充本地目录已有/缺失、远端目录相同/更新、单标签/全库同步、旧文件清理和信息查询等状态转换。

## 3. 实验取舍

| 实验 | 决定 | 理由与最小规模 |
|---|---|---|
| 合成NetCDF生产正确性 | **保留，核心** | 直接验证老师要求的`lon-lat`、`lat-lon`及二维/三维转换；用代表性组合覆盖关键分支，不以案例数量作为贡献 |
| 网页YAML生成器契约测试 | **新增，核心** | 验证网页生成的YAML能被流水线直接解析和运行；必须先移除`TARBALL`及硬编码路径不一致 |
| 新贡献者按文档复现流程 | **新增，核心但小样本** | 2～3名未参与代码开发者，各完成1个受控数据集；报告完成率、干预点和文档修订，不做泛化用户研究 |
| `.nc`与`tar.gz`效率比较 | **保留，降为支持实验** | 老师提出取消二次压缩以减少额外步骤；选择小、中、大3类文件，重点报告首次读取时间和临时磁盘，不需大规模网络基准 |
| Collector公共接口回归 | **新增，核心** | 覆盖update/download/sync/clean/tree/info和`read_dataset`，验证状态转换及向后兼容 |
| 多镜像、cache、SHA及故障注入 | **保留，核心** | 是讨论中明确的新逻辑；受控HTTP场景优先，Linux/macOS/Windows各跑；真实网络只作少量外部有效性检查 |
| 多镜像真实网络大量重复 | **缩减** | 镜像性能随时间和地点变化，3～5个标签每种网络3～5次即可说明外部行为，不外推全库 |
| `grid_dict/grid_weather`金标准 | **保留，核心** | 验证新接口的字段、数值、单位、时间长度和边界行为 |
| 完整Emerald长期模拟 | **删除** | 超出框架更新论文问题；改为初始化成功和最小步进烟雾测试 |
| 代码行数和人工调用数比较 | **删除或仅作附录描述** | 定义主观、可重复性弱，不能替代数值正确性；贡献流程复现更有说服力 |
| Server/Requestor测试 | **删除** | 老师明确排除，且涉及独立的网络安全问题 |
| TOML与YAML格式性能比较 | **不做** | 格式选择不是科学贡献，目录规模下意义有限 |

## 4. 修订后的研究问题

- **RQ1 数据生产与贡献复现**：网页生成的YAML和处理流水线能否把代表性二维/三维异构NetCDF正确转换为标准数据，并使未参与开发的贡献者按文档完成数据登记？
- **RQ2 数据分发可靠性**：直接NetCDF、独立目录、多镜像、cache和SHA校验能否在三种操作系统及受控故障下保持下载内容和正式目录状态正确？
- **RQ3 公共接口稳定性**：Collector目录管理操作与`read_dataset`重载能否在本地/远端不同状态下得到确定结果，并保留必要的旧接口兼容性？
- **RQ4 模型初始化接口**：`grid_dict`和`grid_weather`能否生成与独立金标准一致、可用于Emerald固定格点初始化和最小步进的数据？

## 5. 投稿前不可省略的软件改动

1. 在目录中登记文件字节数和SHA-256，下载完成后校验，只有校验通过才从cache进入public。
2. 修复全部镜像失败和残留cache条件下仍可能移动文件的问题。
3. 使镜像探测不依赖Unix专用ping；至少为Windows和禁止ICMP场景提供协议级回退。
4. 统一网页YAML生成器、YAML schema和`process_dataset!`字段，移除遗留`TARBALL`，取消硬编码保存路径。
5. 明确并测试源维度映射；当前代码不能直接处理任意`(lat,lon)`或`(ind,lat,lon)`排列。
6. 为Collector、`read_dataset`、`grid_dict`和`grid_weather`建立真正执行断言的自动测试，而不是只执行后`@test true`。

完成以上改动并冻结release后，论文才能从“设计和审计初稿”进入“有实验证据的投稿稿”。
