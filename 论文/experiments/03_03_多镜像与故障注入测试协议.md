# 实验3.3：Collector操作、多镜像与故障注入测试协议

## 1. 研究问题

验证Collector公共操作在不同本地/远端状态下的确定行为，并检验论文release的“协议探测—逐URL下载—cache校验—正式落盘”逻辑在三种操作系统和故障条件下能否保持内容及目录状态正确。

## 2. 公共操作状态矩阵

在隔离临时根目录建立小型远端目录、旧本地目录、2～3个小型NetCDF和双镜像。覆盖本地目录不存在/相同/落后、远端目录损坏及断网状态，逐项测试初始化与加载、`update_database!`、`download_dataset!`、`sync_database!`、`clean_database!`三类行为、目录树、数据集信息查询、`read_dataset`四类重载及`read_LUT`兼容别名。每项至少重复3次，并断言返回值、内存标签、目录版本、cache/public和幂等行为。破坏性操作只允许指向已验证位于临时根目录内的路径。

## 3. 镜像测试层级

### 3.1 受控本地镜像

建立两个内容相同的HTTP测试端点，并可独立设置延迟、限速、状态码、截断、连接重置和错误响应。测试不依赖真实FTP/Zenodo，也不写用户真实`~/GriddingMachine`；数据根目录必须可重定向到临时目录，否则先将路径参数化。

### 3.2 真实镜像观察

从补齐`SIZE/SHA256`且具有多个URL的标签中固定3～5个小中型文件，在中科大校内网络和至少一种校外网络运行。真实镜像只用于观察，不主动制造故障，也不据少量标签推断全库状态。

## 4. 场景矩阵

| 编号 | 场景 | 重点观察 |
|---|---|---|
| M01 | 两镜像均可用、延迟不同 | 排序、首选地址和总时间 |
| M02 | 首选返回404，第二成功 | 是否回退及错误日志 |
| M03 | 首选超时，第二成功 | 超时成本和最终成功率 |
| M04 | 首选连接重置，第二成功 | 缓存残留及覆盖行为 |
| M05 | HTTP可用但ICMP被禁 | 是否被错误判为不可达 |
| M06 | 两镜像协议探测成功但下载均失败 | 是否保持正式文件及最终异常 |
| M07 | 所有协议探测失败 | 是否仍逐URL尝试及错误信息 |
| M08 | 缓存已有同名完整旧文件 | 失败后是否误移动旧缓存 |
| M09 | 缓存已有截断文件 | 正式目录是否被污染 |
| M10 | 返回200但内容为HTML | 是否被当作NetCDF保存 |
| M11 | 文件中途截断 | 下载调用、缓存和正式目录状态 |
| M12 | 正式文件已存在 | 是否直接返回且不检查内容 |
| M13 | 字节数正确但SHA-256错误 | 是否拒绝进入正式目录 |

M01～M13分别在Linux、macOS和Windows运行。论文release应使用文件协议级探测或提供不依赖Unix ping的回退；Windows和禁止ICMP场景必须作为通过条件，而不只是记录已知失败。

## 5. 指标

- 镜像可达性判断的真阳性、假阳性和假阴性。
- 选择的首个URL、回退次数、最终成功率和端到端时间。
- 连接时间、首字节时间、吞吐率及各阶段错误类型。
- cache和public路径在运行前后的文件存在性、大小和SHA-256。
- 错误信息是否包含标签、URL和失败阶段。

## 6. 重复与统计

- 受控场景每个平台组合至少重复5次；真实网络组合重复3～5次。
- 网络场景按平台、网络和数据文件分层报告，不把校内与校外样本直接合并。
- 时间指标报告中位数、四分位距和95%置信区间；成功率报告分子和分母。
- 故障注入的首要结果是状态正确性，不以速度代替正确性。

## 7. 当前状态与release通过标准

基线的Unix专用ping、ICMP误判、缺少哈希和失败后移动残留cache问题已在本地论文提交`ad5a5b3`中修复。Windows函数级fixture中，目录/镜像/缓存相关27项自动断言通过。2026-08-09又完成Windows源码级受控HTTP矩阵：M01～M13各重复5次，共65次状态断言通过，结果见`03_03_Windows受控HTTP结果.md`。该harness直接载入论文分支的`dataset-download.jl`，但不是完整包环境，也不是三平台或真实镜像复测。

正式release仍须在Linux、macOS和Windows满足：正确镜像可用时获得与目录SHA-256一致的文件；全部镜像失败、HTML、截断或哈希错误时返回明确错误；本次cache被清理；上一有效目录和正式文件保持不变。
