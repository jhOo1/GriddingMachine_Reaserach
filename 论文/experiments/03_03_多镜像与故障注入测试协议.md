# 实验3.3：Collector操作、多镜像与故障注入测试协议

## 1. 研究问题

验证Collector公共操作在不同本地/远端状态下的确定行为，并检验论文release的“协议探测—逐URL下载—cache校验—正式落盘”逻辑在Windows受控故障条件下能否保持内容及目录状态正确。

## 2. 公共操作状态矩阵

在隔离临时根目录建立小型远端目录、旧本地目录、2～3个小型NetCDF和双镜像。覆盖本地目录不存在/相同/落后、远端目录损坏及断网状态，逐项测试初始化与加载、`update_database!`、`download_dataset!`、`sync_database!`、`clean_database!`三类行为、目录树、数据集信息查询、`read_dataset`四类重载及`read_LUT`兼容别名。每项至少重复3次，并断言返回值、内存标签、目录版本、cache/public和幂等行为。破坏性操作只允许指向已验证位于临时根目录内的路径。

## 3. 镜像测试层级

### 3.1 受控本地镜像

建立两个内容相同的HTTP测试端点，并可独立设置延迟、限速、状态码、截断、连接重置和错误响应。测试不依赖真实FTP/Zenodo，也不写用户真实`~/GriddingMachine`；数据根目录必须可重定向到临时目录，否则先将路径参数化。

### 3.2 真实FTP—Zenodo访问实验

从补齐`SIZE/SHA256`且同时具有机构FTP与Zenodo URL的标签中固定3～5个小中型文件，在中科大校园网实际运行。对每个URL分别执行Windows ping和完整文件只读下载，记录延迟、成功状态、下载耗时、字节数和SHA-256；随后调用论文版本的实际排序与回退流程。FTP只在校园网可访问，因此校外失败不作为软件失败，也不得用本地HTTP夹具替代本实验。所有下载写入研究目录的隔离缓存，不对远端执行上传、覆盖或删除。

## 4. 场景矩阵

| 编号 | 场景 | 重点观察 |
|---|---|---|
| M01 | 两镜像均可用、注入ping不同 | 是否优先选择较低ping地址 |
| M02 | 首选返回404，第二成功 | 是否回退及错误日志 |
| M03 | 第一镜像ping为`Inf`、第二有限 | 是否把有限值排在`Inf`之前 |
| M04 | 首选连接重置，第二成功 | 缓存残留及覆盖行为 |
| M05 | 唯一镜像ping为`Inf`但可下载 | 是否仍保留并尝试该URL |
| M06 | 两镜像下载均失败 | 是否保持正式文件及最终异常 |
| M07 | 所有ping为`Inf`且下载失败 | 是否仍逐URL尝试及保留错误信息 |
| M08 | 缓存已有同名完整旧文件 | 失败后是否误移动旧缓存 |
| M09 | 缓存已有截断文件 | 正式目录是否被污染 |
| M10 | 返回200但内容为HTML | 是否被当作NetCDF保存 |
| M11 | 文件中途截断 | 下载调用、缓存和正式目录状态 |
| M12 | 正式文件已存在且完整 | 是否校验后直接返回且无网络请求 |
| M13 | 字节数正确但SHA-256错误 | 是否拒绝进入正式目录 |

M01～M13在Windows运行。论文release以Windows `ping`结果排序URL；受控矩阵通过注入固定ping分数验证顺序，并保留“ping无响应但文件可下载”场景，要求该URL仍进入下载尝试队列。

## 5. 指标

- 注入ping分数对应的排序、`Inf`保序和下载尝试行为。
- 选择的首个URL、回退次数、最终成功率和端到端时间。
- 连接时间、首字节时间、吞吐率及各阶段错误类型。
- cache和public路径在运行前后的文件存在性、大小和SHA-256。
- 错误信息是否包含标签、URL和失败阶段。

## 6. 重复与统计

- Windows受控场景每个组合至少重复5次；真实FTP和Zenodo每个文件—镜像组合至少重复3次。
- 真实结果按文件和镜像分别报告，不与回环HTTP结果合并。
- 时间指标报告中位数、四分位距和95%置信区间；成功率报告分子和分母。
- 故障注入的首要结果是状态正确性，不以速度代替正确性。

## 7. 当前状态与release通过标准

Windows ping解析与排序已在`53bb0be`恢复，完整包63/63通过，其中两项覆盖正常ping响应和超时解析。当前包级M01～M13使用固定注入ping分数完成65/65次状态断言：覆盖低延迟排序、`Inf`保序、回退、缓存隔离、截断、大小与SHA-256错误以及正式文件保护。校园网真实FTP—Zenodo实验已于2026-08-15执行，FTP与Zenodo共24/24次通过`SIZE/SHA256`。

正式release在Windows须满足：正确镜像可用时获得与目录SHA-256一致的文件；全部镜像失败、HTML、截断或哈希错误时返回明确错误；本次`.part`缓存被清理；上一有效目录和正式文件保持不变。本文不作其他操作系统声明。
