# 实验3.3：多镜像、跨平台与故障注入测试协议

## 1. 研究问题

描述当前“ping排序—逐URL下载—cache移动”算法在不同操作系统和故障条件下的实际行为，检验镜像回退能否完成下载，并确定哪些失败会使正式数据路径或缓存处于错误状态。

## 2. 测试层级

### 2.1 受控本地镜像

建立两个内容相同的HTTP测试端点，并可独立设置延迟、限速、状态码、截断、连接重置和错误响应。测试不依赖真实FTP/Zenodo，也不写用户真实`~/GriddingMachine`；数据根目录必须可重定向到临时目录，否则先将路径参数化。

### 2.2 真实镜像观察

从当前具有FTP和Zenodo双URL的72个标签中固定3～5个小中型文件，在中科大校内网络和至少一种校外网络运行。真实镜像只用于观察，不主动制造故障，也不据少量标签推断全库状态。

## 3. 场景矩阵

| 编号 | 场景 | 重点观察 |
|---|---|---|
| M01 | 两镜像均可用、延迟不同 | 排序、首选地址和总时间 |
| M02 | 首选返回404，第二成功 | 是否回退及错误日志 |
| M03 | 首选超时，第二成功 | 超时成本和最终成功率 |
| M04 | 首选连接重置，第二成功 | 缓存残留及覆盖行为 |
| M05 | HTTP可用但ICMP被禁 | 是否被错误判为不可达 |
| M06 | 两镜像ping有限但下载均失败 | 是否仍执行`mv`及最终异常 |
| M07 | 所有ping为Inf | 错误阶段和信息 |
| M08 | 缓存已有同名完整旧文件 | 失败后是否误移动旧缓存 |
| M09 | 缓存已有截断文件 | 正式目录是否被污染 |
| M10 | 返回200但内容为HTML | 是否被当作NetCDF保存 |
| M11 | 文件中途截断 | 下载调用、缓存和正式目录状态 |
| M12 | 正式文件已存在 | 是否直接返回且不检查内容 |

M01～M12分别在Linux、macOS和Windows运行。Windows重点记录当前Unix风格ping命令的失败行为。

## 4. 指标

- 镜像可达性判断的真阳性、假阳性和假阴性。
- 选择的首个URL、回退次数、最终成功率和端到端时间。
- 连接时间、首字节时间、吞吐率及各阶段错误类型。
- cache和public路径在运行前后的文件存在性、大小和SHA-256。
- 错误信息是否包含标签、URL和失败阶段。

## 5. 重复与统计

- 受控场景每个组合重复至少20次；真实网络组合至少10次。
- 网络场景按平台、网络和数据文件分层报告，不把校内与校外样本直接合并。
- 时间指标报告中位数、四分位距和95%置信区间；成功率报告分子和分母。
- 故障注入的首要结果是状态正确性，不以速度代替正确性。

## 6. 当前预期边界

- Windows预计无法解析当前ping命令。
- 禁止ICMP但允许HTTP的端点预计被判为不可达。
- 没有哈希时，错误HTML、静默截断或旧缓存可能无法被识别。
- 所有有限ping镜像下载失败时，当前代码仍可能进入`mv`。

以上均为待实验验证的代码推断，不作为实测结果。
