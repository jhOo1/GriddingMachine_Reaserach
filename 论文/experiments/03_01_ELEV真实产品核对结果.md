# 实验3.1补充结果：ELEV真实标准产品核对

更新日期：2026-08-09

## 1. 目的与边界

本实验使用已经过目录大小和SHA-256校验的`ELEV_4X_1Y_V1.nc`，核对NetCDF底层读取、GriddingMachine统一读取以及GriddingMachineDatasets无损再处理是否保持数组、坐标和元数据结构。由于原始MERIT DEM源文件及可确认的原始处理环境不在本地，本实验是“真实标准产品读取与无损再处理”，不是从原始来源重建科学产品。

## 2. 输入

- 文件大小：810,299 B。
- 文件SHA-256：`642a485fda9517d267a71a63f8cbbb79b924bb19b2ff18a6471c0305b5be6f0f`。
- `data`形状：1440×720，单位m，无NaN。
- 有限值范围：-415.5～5357.7002 m。
- 经度中心：-179.875°～179.875°；纬度中心：-89.875°～89.875°。

## 3. 读取与再处理结果

`GriddingMachine.Indexer.read_dataset("ELEV_4X_1Y_V1")`与`NetcdfIO.read_nc(Float32, ..., "data")`逐元素`isequal`，数组SHA-256为`a569143037e2e01cb101e094439255aef5a4d62f99fbe45baa55323ff77e6750`。

随后将同一真实标准文件复制到纯ASCII隔离输入目录，使用显式`DIMENSIONS=[lon,lat]`、`GAPFILL=KEEP_AS_IS`、无缩放和无范围裁剪的配置调用`process_dataset!`，独立重复3次。三次的`data`、`lon`和`lat`均与输入完全一致，审核替身各调用1次；三份输出均为654,671 B，SHA-256均为`08dfc8472c3574e73daf2add605efba1e8dd35d9769937ef227c944a272159c3`。文件大小不同来自重新编码，不影响本实验比较的科学数组和坐标。

## 4. 功能验收与历史配置边界

本研究按`test/preparation/griddingmachine-v04/catergory.txt`验收当前产品的数值与缺失值行为。ELEV对应规则为“陆地区域不得为NaN”；本文件全域无NaN，因此满足更强条件。该判断不依赖文件是否为2022年原始生产批次，也不要求恢复当时的原始输入。

仓库现有`yaml/community/ELEV_4X_1Y_V1.yaml`登记的范围、单位和修订标签与当前文件不一致，因此不能作为当前产品的完整生产溯源。本轮不猜测性修改历史YAML；该遗留元数据迁移可在后续维护中处理，不阻塞本文关于当前标准文件可被统一读取、满足类别规则并经流水线无损处理的结论。

## 5. 环境

GriddingMachine提交`fe46788`，ELEV核对运行时GriddingMachineDatasets提交`064ce1d`；其后软件可用性修复提交为`3926ae3`。环境为Windows 10、Julia 1.12.6。全过程网络请求数为0，临时NetCDF在运行结束后删除。
