# Release v0.5.0

Merges the 0.5.0 line into `main`. `origin/main` (`0cd6cbe`, v0.4.0) is an ancestor of this
branch, so nothing on `main` is dropped. `paper-release`, `wyujie` and `staging` are ancestors
too. `jianghao` is not merged as a branch: its query-server work was reimplemented here (see
below), and the one Collector feature it carried, `remove_empty_folders!`, was ported.

94 files, +4797 / -1487 relative to `main`. 377 tests, all passing on Ubuntu, macOS and Windows
with Julia 1.12.6, at 97.6% line coverage.

## Suggested reading order

Most of the diff is mechanical. To review the parts that need judgement:

1. `src/Server/` (8 files, all new or rewritten) — the query server, the largest new piece
2. `src/Collector/database-download.jl`, `database-clean.jl`, `database-remove-folder.jl` — the
   three behaviour changes outside `Server`
3. `docs/superpowers/specs/2026-09-01-server-web-design.md` — why the server is shaped this way,
   including the trade-offs listed under "open questions" below
4. `README.md` — user-facing API and the v0.4 to v0.5 migration notes
5. `test/` (12 files) — the offline fixtures, if you want to check that no test touches the network

Skippable: 26 files under `deprecated/` are moved sources, unchanged in content.

## Breaking changes

- `Collector.download_artifact!` -> `Collector.download_dataset!`
- `Collector.query_collection` -> `Collector.dataset_path` / `Collector.dataset_info`
- `Requestor.request_site_data` now takes the server URL and user name first:
  `(server, user, tag, lat, lon, cycle = 0)`; the `interpolation` keyword is gone
- `Blender` removed; `regrid` now comes from `PkgUtility.MathTools`
- `Fetcher` removed; downloading raw ungridded data is handled by GriddingMachineDatasets
- `Partitioner` and `Processer` removed (both were already commented out and never loaded in v0.4)
- `Indexer` no longer interpolates between grid cells; a site read returns the containing cell
- `using GriddingMachine` no longer creates directories or downloads the catalog as an import
  side effect; call `Collector.initialize_database!()` or `Collector.update_database!()`
- The query endpoints now require `lat` and `lon`. Earlier versions substituted a fixed default,
  so a request without coordinates was answered with data for an unrelated grid cell.
- `Server.setup_url_input_routes!` no longer refuses a request whose `user` is outside
  `allowed_users`. That check could not work: `user` arrives as a query parameter, so any caller
  could set it to a permitted value. The argument is now only used for the startup log line.
- `clean_database!` now also removes the directories that become empty.
- Minimum Julia is 1.12. The compat bound previously said 1.10, but `PkgUtility` 0.3 requires 1.12,
  so installing on 1.10 or 1.11 failed with an unsatisfiable resolver error. The declaration now
  matches what actually resolves, and CI covers exactly that range.

`Indexer.read_LUT` is kept as an alias of `read_dataset`. Sources of the removed sub-modules are
under `deprecated/` for reference only; they are not compiled.

## Distribution and integrity

- Catalog entries carry `SIZE` and `SHA256`. A download goes to a cache file first and is only
  promoted after both match, so an interrupted or corrupted download never replaces a valid file.
- Catalog updates are transactional; a catalog that fails validation leaves the previous one in
  place, kept as `Artifacts.previous.yaml`.
- `Collector.validate_catalog` rejects malformed entries, including a `PATH` that would escape the
  data directory.
- A tag may list several mirrors. Candidates are ordered by a reachability probe and tried in turn;
  a mirror that fails the probe is still attempted, because an unanswered ICMP probe does not mean
  the file cannot be fetched over HTTP(S) or FTP.

## Query server (new)

`Server` serves a query page at `/` plus three JSON endpoints: `/sitedata.json` (one dataset value
at one grid cell), `/gmdict.json` (land parameter dictionary) and `/weather.json` (weather driver
series). The page queries those same endpoints from the browser, so the interface and the API share
one code path and there are no form-post routes.

This is a reimplementation of the `jianghao` work rather than a merge. Twelve defects in that
branch were verified and are fixed here; the ones worth naming:

- the dataset selector was always empty, because the tag list was read at include time while
  `YAML_TAGS` is only populated when `load_database!` runs
- `YAML_FILE_TIME` was referenced but never defined, so the unknown-tag branch raised
  `UndefVarError`
- `parse(Bool, ...)` raised on `?include_std=1`
- the collection selector offered `gm3` and `gm4`, which `LandDatasetLabels` does not support
- the POST result routes bypassed the user check entirely and hardcoded `"Anonymous"`
- `catch e` returned `string(e)` to the client

Route count went from 12 to 4, two HTML templates were merged into one, and about 420 lines of
duplicated code are gone.

## Bug fixes found while testing this branch

Three defects that predate this work, all with regression tests:

- **`Collector.update_database!` was unusable on Julia 1.12.** Resolving the catalog URL from a
  landing page (the default path) returned the regex match, a `SubString`, and
  `Downloads.download` hands the url straight to libcurl, which has no `Cstring` conversion for
  `SubString`. The existing test covered that branch but asserted with `==`, and a `String` equals
  the `SubString` with the same content, so the type defect passed. The test now asserts
  `isa String` on every branch.
- **`/sitedata.json` leaked internal detail.** A dataset whose mirrors are all unreachable raised,
  so the request was answered with HTTP 500 and a plain-text body carrying the full stacktrace, the
  absolute source paths of the installation, and every mirror url tried, including institutional
  hosts. It now answers HTTP 200 with `Reason: "dataset unavailable"`; the exception only reaches
  the log. The other two endpoints already behaved this way.
- **`CO₂_ppm(yy, mm)` raised `TypeError`.** It joined two `BitVector`s with `&&` instead of `.&&`.
  The function had no caller, so nothing had exercised it.

## Testing

377 tests, 97.6% line coverage, every file under `src/Server` fully covered.

The land parameter and weather endpoints are tested offline: the fixtures write tiny NetCDF files
and register them in a temporary catalog, so no test downloads a real dataset and no test reaches
the network. Downloads are injected through the `downloader` / `probe` keywords, and the network
paths that must be exercised are served from `localhost`. Failure paths assert that a response body
carries no stacktrace, no mirror url and no local path.

## Open questions for review

Deliberate trade-offs that a reviewer may want to overrule:

1. **The server has no access control and binds `0.0.0.0`.** This is about exposure, not about
   whether the endpoints work. It is documented as being for a local or trusted intranet network,
   and the `user` parameter is labelled in code and docs as a log field rather than a credential.
   The alternative considered was an optional token; it was left out because the deployment target
   is a lab network. Because the land parameter and weather endpoints assemble a whole collection
   on demand, an instance reachable by an untrusted network can also be driven to fetch hundreds of
   megabytes per request. Whether that is acceptable is a decision for whoever operates the
   instance, which is why it is listed here rather than settled in the code.
2. **Failure classification matches on upstream error message text.** `grid_dict` signals "no land"
   and "not vegetated" through `ErrorException` messages, and `Collector` reports an exhausted
   mirror list the same way. Re-deriving those conditions in the server would duplicate logic that
   lives in `Indexer`. The tests pin every mapping, so an upstream wording change fails the suite
   rather than silently degrading to `internal error`.
3. **An unknown tag no longer refreshes the catalog.** A typo against a catalog of over a thousand
   entries used to re-download the whole catalog, about twelve seconds where the answer now takes a
   tenth of a second. The cost is that a tag published upstream since the last refresh is reported
   as unknown until `update_database!` is called.
4. **The design document is committed under `docs/superpowers/specs/`.** It records why the server
   is shaped this way and which trade-offs were made, so it seemed worth keeping next to the code.
   The step-by-step implementation plan was deliberately not committed here; it lives in the
   research repository as development history.
